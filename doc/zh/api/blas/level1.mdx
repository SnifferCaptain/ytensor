# BLAS Level-1

Level-1 处理向量上的 O(n) 运算。普通用户最常用的是 `sdot` 和 `hdot`；`dotxv`、`axpyv`、`dotxf`、`axpyf` 以及 panel packing 主要用于编写新的 BLAS frame 或高性能算子。

## 接口概览

| 接口 | 功能 | 适用场景 |
| --- | --- | --- |
| `sdot` | FP32 向量点积 | 直接处理 `float*` |
| `hdot` | FP16 输入、FP32 累加的向量点积 | 直接处理 `float16*` |
| `dotxv` | 带 `alpha/beta` 的点积原语 | 组合底层算子 |
| `axpyv` | `y += alpha * x` | 组合 GEMV、GER 等算子 |
| `scalv`、`setv` | 向量缩放、赋值 | 输出初始化或缩放 |
| `dotxf`、`axpyf` | 一次遍历融合多个向量操作 | 构建 Level-2 frame |
| `pack_a_typed_panel`、`pack_b_typed_panel` | 矩阵 panel packing | 构建 Level-3 或类 GEMM 算子 |

## `sdot`

计算两个 FP32 向量的点积：

```cpp
float yt::blas::sdot(
    const float* x,
    const float* y,
    int n,
    int64_t incx = 1,
    int64_t incy = 1
);
```

### 参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `x` | `const float*` | 第一个向量的逻辑首元素 |
| `y` | `const float*` | 第二个向量的逻辑首元素 |
| `n` | `int` | 参与运算的元素数 |
| `incx` | `int64_t` | `x` 相邻逻辑元素之间的元素步幅，默认为 `1` |
| `incy` | `int64_t` | `y` 相邻逻辑元素之间的元素步幅，默认为 `1` |

### 返回值

返回：

```text
Σ x[i * incx] * y[i * incy]
```

当 `n <= 0` 时返回 `0`。

### 连续向量

```cpp
#include <iostream>
#include "ytensor.hpp"

int main() {
    float x[] = {1.0f, 2.0f, 3.0f};
    float y[] = {4.0f, 5.0f, 6.0f};

    float result = yt::blas::sdot(x, y, 3);
    std::cout << result << '\n';  // 32
}
```

### 跳过间隔元素

下面只读取 `x` 中下标为 `0、2、4` 的元素：

```cpp
float x[] = {1.0f, 99.0f, 2.0f, 99.0f, 3.0f};
float y[] = {4.0f, 5.0f, 6.0f};

float result = yt::blas::sdot(x, y, 3, 2, 1);
// 1*4 + 2*5 + 3*6 = 32
```

`incx = 2` 的单位是两个 `float` 元素，而不是 `2 * sizeof(float)` 字节。

### 反向遍历

负步幅不会自动把 pointer 移动到数组末尾，调用方必须传入逻辑首元素：

```cpp
float x[] = {1.0f, 2.0f, 3.0f};
float y[] = {10.0f, 20.0f, 30.0f};

float result = yt::blas::sdot(x + 2, y, 3, -1, 1);
// 3*10 + 2*20 + 1*30 = 100
```

如果这里传入 `x` 而仍使用 `incx = -1`，第二次读取就会越过数组起点。

## `hdot`

`hdot` 接收 FP16 storage，使用 FP32 完成乘法累加，并返回 `float`：

```cpp
float yt::blas::hdot(
    const yt::float16* x,
    const yt::float16* y,
    int n,
    int64_t incx = 1,
    int64_t incy = 1
);
```

示例：

```cpp
yt::float16 x[] = {
    yt::float16(1.0f),
    yt::float16(2.0f),
    yt::float16(3.0f)
};
yt::float16 y[] = {
    yt::float16(4.0f),
    yt::float16(5.0f),
    yt::float16(6.0f)
};

float result = yt::blas::hdot(x, y, 3);
// result == 32.0f
```

输入值在存入 `float16` 时已经发生一次精度舍入，但点积不会使用 FP16 累加。

## 底层向量原语

以下接口适合在新的 frame 中复用。它们不分配内存、不创建线程，也不检查 pointer 所指 storage 的容量。

### `dotxv`

```cpp
template <typename Storage>
float yt::blas::dotxv(
    int n,
    float alpha,
    const Storage* x,
    int64_t incx,
    const Storage* y,
    int64_t incy,
    float beta,
    float rho
);
```

计算：

```text
rho_out = beta * rho + alpha * Σ(x[i] * y[i])
```

当 `beta == 0` 时不会读取 `rho`。这适合让上层 frame 在覆盖输出时避免读取未初始化值。

### `axpyv`

```cpp
template <typename XStorage, typename YStorage>
void yt::blas::axpyv(
    int n,
    float alpha,
    const XStorage* x,
    int64_t incx,
    YStorage* y,
    int64_t incy
);
```

计算：

```text
y[i] = y[i] + alpha * x[i]
```

当前支持的 storage 组合为：

| `x` | `y` |
| --- | --- |
| `float` | `float` |
| `float16` | `float16` |
| `float16` | `float` |

### `scalv` 与 `setv`

```cpp
template <typename Storage>
void yt::blas::scalv(
    int n,
    float beta,
    Storage* x,
    int64_t incx
);

template <typename Storage>
void yt::blas::setv(
    int n,
    float value,
    Storage* x,
    int64_t incx
);
```

`scalv` 计算 `x *= beta`，`setv` 将每个逻辑元素设为同一个值。当 `beta == 0` 时，`scalv` 不读取原始元素。

## 融合向量原语

Level-1f 通过一次遍历计算多个相关输出，主要由 GEMV frame 使用。

### `dotxf`

```cpp
template <typename Storage>
void yt::blas::dotxf(
    const yt::blas::BlasContext& context,
    int n,
    int f,
    float alpha,
    const Storage* x,
    int64_t incx,
    const Storage* a,
    int64_t rsa,
    int64_t csa,
    float beta,
    float* y,
    int64_t incy
);
```

其中：

```text
a(i,j) = a[i * rsa + j * csa]
y[j] = beta*y[j] + alpha*Σ_i(x[i] * a(i,j))
```

`f` 是本次融合处理的输出数。默认 context 的融合宽度为 `df = 4`；不满足快速路径条件时，接口会组合多个 `dotxv`，计算合同不变。

### `axpyf`

```cpp
template <typename Storage>
void yt::blas::axpyf(
    const yt::blas::BlasContext& context,
    int n,
    int f,
    float alpha,
    const Storage* a,
    int64_t rsa,
    int64_t csa,
    const Storage* x,
    int64_t incx,
    float* y,
    int64_t incy
);
```

计算：

```text
y[i] += alpha * Σ_j(a(i,j) * x[j])
```

默认融合宽度为 `af = 8`。`dotxf` 和 `axpyf` 的 `y` 当前使用 FP32 storage；FP16 GEMV 的最终转换由 Level-2 frame 负责。

## Panel packing

Level-1m 的 typed packer 是 Level-3 和卷积类算子的内部构件。一般用户不应为了调用 GEMM 而手动 packing，`sgemm`、`hgemm` 会完成这一步。

```cpp
template <typename SourceType, typename ComputeType, GemmKernelSpec Spec>
void yt::blas::pack_a_typed_panel(
    const SourceType* A,
    ComputeType* packed,
    int mc,
    int kc,
    int64_t rsa,
    int64_t csa
);

template <typename SourceType, typename ComputeType, GemmKernelSpec Spec>
void yt::blas::pack_b_typed_panel(
    const SourceType* B,
    ComputeType* packed,
    int kc,
    int nc,
    int64_t rsb,
    int64_t csb
);
```

当前默认 packed layout 使用 `MR = 6`、`NR = 16`：

```text
A panel: [kc][MR]
B panel: [kc][NR]
```

边缘位置由 packer 补零。FP16 源数据在 packing 时转换为 FP32，因此物理 GEMM 微内核不需要复制一套 FP16 算法。

:::warning
Packer 由调用方提供目标 buffer。buffer 容量、对齐要求和源/目标不重叠都必须由调用方保证；除非正在实现新的底层算子，否则请使用 Level-3 公共接口。
:::

## 性能与使用建议

- 连续向量优先使用默认 `incx = incy = 1`，这是 SIMD 最有利的布局；
- 大步幅和负步幅仍保持相同计算语义，但内存访问通常更慢；
- Level-1 本身不创建线程，短向量也不会承担并行调度成本；
- 不要为了使用 `dotxv`、`axpyv` 而复制 dtype 分支，应通过 storage 模板组合；
- 裸指针接口不做边界检查，无法证明容量时应回到 `YTensor` 接口。
